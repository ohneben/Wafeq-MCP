# spec/

`wafeq-public-api.json` is the Wafeq Public API OpenAPI 3.1.1 document:
107 paths, 251 operations, 230 schemas, servers `https://api.wafeq.com/v1`.

## Where it came from

Wafeq does not publish a downloadable spec file. Their documentation site
(`developer.wafeq.com`, ReadMe-hosted) embeds the complete document in the page
payload of every `/reference/*` page, under `filename: wafeq-public-api.json`. This
copy was extracted from there on **2026-09-04**, unmodified apart from
pretty-printing.

The agent-facing index at <https://developer.wafeq.com/llms.txt> lists the same
endpoints and is a good way to check whether the API has grown.

## Updating it

Tools are generated from this file at startup — there is no code generation step and
no hand-written tool list. To pick up new endpoints:

1. Drop a newer OpenAPI document in as `spec/wafeq-public-api.json`
   (JSON or YAML; both load).
2. `npm run build && npm test && npm run list-tools`.

The tests assert the counts of the bundled spec (251 operations, the category
totals, 146 endpoints carrying the idempotency header). A newer spec will move those
numbers — update the expected values once you have confirmed the new catalogue looks
right. Everything else is derived, so no source changes are needed.

To try a spec without replacing this file, point `WAFEQ_OPENAPI_PATH` at it.

## Notes on the source document

- It is generated by drf-spectacular, which reuses one schema for requests and
  responses. Server-assigned fields are marked `readOnly` **and** listed in
  `required`; `src/openapi.ts` strips them from request bodies. See
  `stripReadOnly` for why.
- `__in` filters are declared `explode: false` (comma-separated); `status__in` is
  `explode: true` (repeated key). Both are honoured.
- `/journal-line-items/` is cursor-paginated; everything else uses `page`.
